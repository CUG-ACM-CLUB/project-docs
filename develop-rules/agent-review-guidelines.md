# Agent 审核规则

## 目的

在之前的实践中 , 我们发现 agent code review 后报告的错误倾向于给出夸张的 , 有误导性的 , 未完全理解开发意图的分级 . 比如 , 会把我们后期想要开发的 feature 当做现有的 bug 报告 , 并给出极高的优先度 .

为了解决这个问题 , 我们编写这份文档 , 给出一个可用的评级规则 , 用来指导后续 agent code review . 这份规则用于帮助 Agent 在审核代码和 Issue 时给出更稳定且长期统一的初步判断 .

它不是项目管理制度 , 也不决定 Issue 的开发顺序 , 更不要求所有 agent code review 都遵守 . Agent 给出的等级只是参考 , 最终是否修复 , 是否阻塞其他开发 , 什么时候处理 , 由项目成员决定 .

虽然不是强制要求 , 但是我们呼吁 agent code review 前应该阅读本规范 . 从而尽可能的统一人类与 agent 在审核时的关注点和品味 . 

## 基本规则

1. 先理解当前 Issue、PR、需求范围和验收标准，再开始审核。
2. 当前没有要求的功能，不得直接判断为 bug。
3. 发现问题不等于问题等级很高。普通功能错误不能直接判断为 P0 或 P1。
4. 网络、服务器、模型服务、第三方接口等外部问题，不能直接判断为平台系统故障。
5. 没有足够证据时，不得自行提高问题等级。
6. Agent 不得自行要求暂停开发、阻塞 PR、修改 Issue 类型或开始修复。
7. 无法确认时，应说明缺少什么证据，并标记为待人工确认。

## 参考分级

### P0：系统故障

平台整体无法使用，核心服务失效，或发生严重的数据和安全事故。

这类问题需要立即恢复系统。普通接口错误、单个用户失败、单个页面异常，不能直接归为 P0。

### P1：技术债重构

代码积累已经影响后续开发，继续增加功能会明显扩大问题，必须停止相关功能开发，重新规划或进行大范围重构。

普通 bug、单个模块问题、代码风格问题，不能直接归为 P1。

### P2：需要协调的 bug

已经确认是 bug，但修复会影响其他人的模块、接口或开发分支，需要先讨论修复方案、依赖关系和合并顺序。

### P3：可以独立修复的 bug

已经确认是 bug，影响范围明确，可以由负责人独立修复，不需要其他开发者调整自己的工作。

### feature 级

该级别并非是因为 bug , 而是因为项目处于开发初级阶段 , 当前尚未实现的功能 , 有计划或者明知但不计划实现 . 确定是不是 feature 级应该向人类提问有没有做这个 feature 的打算 . agent 可以建议人类将这个功能设置为 feature 级别 , 后续再按照计划决定何时实现(agent可以提出建议 但是最终决定权在人类) . 

新增功能应单独讨论是否加入开发计划，不能因为当前没有实现就阻塞正在进行的 PR。

## 其他情况

### 需求方向调整

产品需求或产品目标发生变化，现有实现需要重新讨论。

需求方向调整不自动等同于 P1。只有确认继续开发会明显增加重构成本时，才考虑归为 P1。

### 外部环境问题

问题来自网络、服务器环境、模型服务、第三方接口或其他外部依赖。

在没有代码证据前，不得判断为平台系统故障。

### 待人工确认

证据不足、影响范围不清楚，或者问题涉及产品方向时，使用“待人工确认”，不要强行分级。

## Agent 的判断顺序

Agent 按以下顺序给出参考判断：

1. 是否已经发生需要立即恢复的系统级故障。如果是，建议 P0。
2. 是否必须停止相关功能开发，重新规划或进行大范围重构。如果是，建议 P1。
3. 是否确认存在 bug，且修复需要其他开发者配合。如果是，建议 P2。
4. 是否确认存在 bug，且负责人可以独立修复。如果是，建议 P3。
5. 是否只是当前尚未实现的新功能。如果是，标记为新增功能。
6. 如果无法证明属于以上情况，标记为待人工确认。

高等级判断必须说明具体依据。不能只因为问题涉及核心功能、多个文件、潜在风险或代码不够优雅，就判断为 P0 或 P1。

## Agent 输出格式

每个审核发现只使用下面的格式：

```text
[建议的参考等级或情况] : 问题描述；判断依据；需要谁配合；对当前 PR 的影响
```

例如：

```text
[建议 P2] : 提交结果没有同步到平台记录；已有验收标准要求保存每次提交结果；需要负责提交同步的开发者确认接口行为；可能影响相关练习记录功能
```

无法判断时使用：

```text
[待人工确认] : 当前证据不足，无法确认问题类型或影响范围；需要补充：具体日志、复现步骤或需求依据
```

Agent 只能给出参考判断，不能自动修改标签、阻塞 PR、改变开发计划或把新增功能当成 bug。
